## What had to change first, and why

Two failures, both pre-existing, both now fixed on that branch.

1. `pagewire.url = "github:bcosynot/pagewire"` names a repo, and nix resolves it to
   that repo's DEFAULT branch. It carried no `flake.nix` until the relay's own PR
   landed, so the input could not be resolved at all. Fixed by the merge.

2. With the input resolvable, evaluation died on:

       error: Failed assertions:
       - The option definition `services.unit' in `…/flake.nix' no longer has any effect;
         please remove it.
         services.unit has been removed together with pkgs.unit.

   NGINX Unit is gone from current nixpkgs and this repo's `webServer` module still
   sets `services.unit`. The repo committed NO `flake.lock` on any branch, so CI
   resolved current nixpkgs — meaning this configuration had never been evaluated
   against a nixpkgs it pins.

   Fixed by committing a `flake.lock` pinning nixpkgs to **0744b52** — the revision
   the box reports running (`nixos-version 26.11.20260802.0744b52`), and one where
   `services.unit` still exists. The flake's own `nixpkgs.url` stays unpinned; the
   lock carries the pin. The lock was generated in CI (a throwaway workflow on a
   `lock-probe` branch, since deleted) against that rev, then its root `nixpkgs`
   node's `original` was set back to the unpinned spec so the flake needed no change.

   That is the CONSERVATIVE half of the choice. The other half is migrating
   `webServer` off NGINX Unit, which would let the repo follow current nixpkgs again
   and drop the pin. It is a real migration: the box still runs `unit.service`.
