---------------------------------------------------------------------
A live surprise that closes an open risk, and opens one

The offline README worried that a real account might refuse the `update_user_book_read`
document, "in particular that `action_at` takes a String variable holding an
offset-bearing timestamp". It did not: the mutation was accepted and the page landed.

But **`action_at` is not a readable field.** Introspecting the live schema:

  query { __type(name: "user_book_reads") { fields { name } } }

returns edition, edition_id, finished_at, finished_at_precision, id, paused_at, progress,
progress_pages, progress_seconds, started_at, user_book, user_book_id. There is no
`action_at`; the datetime fields the read exposes are `started_at`, `finished_at` and
`paused_at`, all `date` scalars.

So criterion 1's "with `action_at` set to when he actually stopped" cannot be verified by
readback: the field is accepted on the mutation input but is not in the queryable schema.
The page half of criterion 1 is proven; the `action_at` half is not readable and is left
open deliberately rather than called met.
